# Native Codex installation on macOS

The Codex console's Install action downloads the native OpenAI Codex executable; Node, npm, Homebrew, and administrator access are not required. The executable is installed in `<app_config_dir>/bin/codex`, normally `~/.bit2-switch/bin/codex`. Version detection and console launches prefer this app-owned executable. Once present, the Codex-only Update action replaces this copy using the same verified installation process. Other tools and externally managed update paths retain their existing lifecycle behavior. The installer does not edit the user's shell PATH.

Installation reads `https://api.github.com/repos/openai/codex/releases/latest`, rejects draft/prerelease metadata, and selects only `codex-aarch64-apple-darwin.tar.gz` or `codex-x86_64-apple-darwin.tar.gz` for the running architecture. The asset must have the exact official GitHub release URL, a positive numeric asset ID, an API URL bound to that ID under `https://api.github.com/repos/openai/codex/releases/assets/`, a valid SHA256 digest, and an expected byte count. Downloads use the constructed first-party asset API URL with `Accept: application/octet-stream`. Redirects are restricted to HTTPS `api.github.com`, `github.com`, and `release-assets.githubusercontent.com`. The archive is verified against metadata before extraction.

Metadata is limited to 2 MiB with a 30-second request timeout. Archive downloads are limited to 128 MiB and 240 seconds. `/usr/bin/tar` streams only the expected executable member to a new private staging file; it never extracts archive paths into the filesystem. Extraction is limited to 30 seconds and 512 MiB. The executable must report the exact release version under a system-only PATH within 10 seconds. The validated file is atomically renamed into place only after these checks pass, preserving any previous working executable on download, digest, extraction, or probe failure. Temporary staging files are removed.

Tests cover altered digests, wrong assets/URLs, unstable release metadata, failed executable probes, preservation of an old installation, private file permissions, and successful atomic replacement. The opt-in network test `downloads_verified_official_native_codex_without_touching_user_path` downloads and probes the actual latest release inside a dedicated temporary directory. That test does not modify the installed user executable or make an API inference request. Its result verifies the tested architecture and network environment only; it does not establish behavior on every fresh macOS version or on Intel hardware when run on Apple silicon.

Codex sessions use separate private persistent directories under `<app_config_dir>/codex-runs/<uuid>`. Installation and update never remove these session histories.

Validation in this implementation run: all six installer tests passed, including the full official GitHub asset API download, SHA256 verification, exact-member extraction, atomic installation into a dedicated temporary directory, and a real `codex-cli 0.154.0` probe with a system-only PATH. The six-test suite completed in 13.82 seconds. No user installation was modified. The initial browser-download transport had timed out; the final implementation uses the verified first-party asset API route described above. Runtime validation was performed on Apple silicon; Intel and other macOS versions remain untested. No API inference requests were made.
